# Duri MVP 데모 QA 가이드

## 실행과 초기화

```bash
npm install
npm run dev
```

기본 주소는 `http://127.0.0.1:5173`이다. 데모를 처음 상태로 되돌리려면 브라우저 개발자 도구의 Application → Local Storage에서 `duri-mvp-store`를 삭제한 뒤 새로고침한다. 저장소 변경을 반영한 배포 빌드는 `npm run build`로 확인한다.

## 라우트 지도

| 경로 | 화면 | 대표 확인 항목 |
| --- | --- | --- |
| `/` | 홈 | 추천 장소, 활성 여행, 주요 진입 버튼 |
| `/explore` | 장소 탐색 목록 | 검색·필터·저장·상세 이동 |
| `/explore/map` | 지도 탐색 | 쿼리 유지, 마커·장소 카드 |
| `/places/:placeId` | 장소 상세 시트 | 저장, 후보 추가, 닫기 |
| `/trips` | 내 여행방 | 진행/완료 구분, 빈 상태 |
| `/trips/new` | 여행방 생성 | 단계별 검증, 생성 후 상세 이동 |
| `/trips/:tripId` | 여행방 홈 | 참여자 응답, 후보·일정 통계 |
| `/trips/:tripId/workspace` | 일정 워크스페이스 | 후보 추가, 일정 편집·삭제, 분석·제안 |
| `/duri` | 두리 허브 | 활성 여행과 분석 진입 |
| `/tests` | 테스트 홈 | 개인 테스트/결과 진입 |
| `/tests/personal` | 개인 성향 테스트 | 6문항, 미응답 시 다음 비활성화 |
| `/tests/personal/result` | 개인 결과 | 저장 결과 또는 테스트 시작 빈 상태 |
| `/saved` | 저장 장소 | 저장 해제, 상세·탐색 이동 |
| `/mypage` | 마이페이지 | 사용자/여행/저장/성향 요약 |
| `*` | 잘못된 주소 | 안전한 안내와 홈 복귀 |

데모 식별자는 여행방 `trip-busan-2026`, 장소 `gamcheon` 등을 사용할 수 있다. 존재하지 않는 `tripId`나 `placeId`도 빈 안내 화면으로 안전하게 처리된다.

## 권장 데모 시나리오

1. `/`에서 활성 부산 여행과 추천 장소를 확인한다.
2. `/tests/personal`에서 문항을 완료하고 결과가 `/tests/personal/result`와 여행방 참여자 응답에 반영되는지 확인한다.
3. `/trips/new`에서 지역·날짜·여행 조건·동행자·제목을 입력해 여행방을 만든다.
4. `/explore`에서 검색/필터를 사용하고 `/explore/map`으로 이동해 같은 검색 조건이 유지되는지 확인한다.
5. 장소 상세에서 저장과 후보 추가를 실행하고 `/saved` 및 여행방 홈에 반영되는지 확인한다.
6. 여행방 홈에서 참여자 응답, 후보 수, 일정 수와 워크스페이스 진입을 확인한다.
7. 워크스페이스에서 후보 보드를 열어 빠른 추가 버튼으로 일정을 추가하고, 카드 편집 시트에서 날짜·시간·체류 시간을 변경한다. 드래그가 어려운 터치 환경에서도 빠른 추가와 편집 시트가 대체 경로다.
8. 일정을 새로고침한 뒤 유지되는지 확인하고 삭제한다. 삭제된 장소는 후보 보드에 남아야 한다.
9. 두리 분석에서 제안 상세와 적용 전 미리보기를 확인하고 제안을 적용한다. 분석 탭을 다시 열어 변경된 일정 기준 결과가 유지되는지 확인한다.
10. `/saved`, `/mypage`, 하단 내비게이션을 순서대로 확인하고 브라우저 뒤로/앞으로 이동을 점검한다.

## 빈 상태·오류 상태 체크리스트

- 여행방 없음: `/trips`에서 새 여행방 만들기 버튼이 보인다.
- 저장 장소 없음: `/saved`에서 장소 둘러보기 버튼이 보인다.
- 테스트 결과 없음: `/tests/personal/result`에서 테스트 시작 버튼이 보인다.
- 탐색 결과 없음: 목록과 지도에서 검색 조건 초기화 버튼이 보인다.
- 후보 없음/필터 결과 없음: 워크스페이스 후보 보드에서 탐색 또는 조건 초기화 버튼이 보인다.
- 제안 없음: 제안 시트에서 일정으로 돌아가는 버튼이 보인다.
- 잘못된 ID/URL: 앱이 충돌하지 않고 홈·목록으로 복귀할 수 있다.
- 잘못된 입력: 여행방 생성 필수값과 개인 테스트 미응답 문항에서 진행이 차단되고 안내가 보인다.
- 예기치 않은 렌더 오류: 사용자용 오류 화면에서 홈 이동 또는 다시 시도를 할 수 있으며 기술 스택은 노출하지 않는다.

## 저장 데이터와 복구 정책

- localStorage 키: `duri-mvp-store`
- Zustand persist 버전: `3`
- 도메인 스키마 버전: `2`
- hydration 때 사용자·지역·장소·여행·후보·일정·성향 결과·저장 관계를 정규화한다.
- 중복 ID/관계는 제거하고, 존재하지 않는 사용자·장소·여행 참조와 잘못된 날짜·시간 일정은 제외한다.
- 누락된 구버전 맵은 데모 기본값으로 보완하되 명시적인 빈 객체/배열은 사용자의 빈 상태로 유지한다.
- 참여자 `preferenceStatus`는 실제 `preferenceResultsByUserId` 존재 여부와 맞춘다.
- 잘못된 JSON, 부분 저장 데이터, 삭제된 엔티티를 참조하는 편집 화면에서도 앱이 충돌하지 않아야 한다.

## 반응형·접근성 체크리스트

- 뷰포트: `360×800`, `375×812`, `390×844`, `430×932`
- 각 크기에서 `/mypage`, `/explore/map`, `/trips/trip-busan-2026/workspace`의 가로 스크롤과 하단 버튼 겹침을 확인한다.
- 모바일 키보드를 연 상태에서 여행방 생성의 다음 버튼과 입력 필드까지 스크롤할 수 있는지 확인한다.
- 장소 상세, 여행방 선택, 일정 편집, 두리 제안은 Escape와 배경/닫기 버튼으로 닫히며 열려 있는 동안 배경 스크롤이 잠긴다.
- 중첩된 여행방 선택 시트는 첫 Escape에 선택 시트만, 다음 Escape에 장소 상세가 닫힌다.
- 아이콘 버튼에는 접근 가능한 이름이 있고, 주요 탭에는 현재 위치가 시각적으로 표시된다.
- 워크스페이스 드래그 핸들은 터치 스크롤 오작동을 줄이기 위해 길게 누르기 지연을 사용한다. 드래그가 어려우면 `일정에 추가`와 일정 편집의 시간 입력을 사용한다.

## 2026-07-13 검수 기록

- Chrome 자동 검수: 홈→테스트→여행방 생성→탐색/지도→저장/후보→워크스페이스→분석/제안→저장/마이페이지 흐름 통과
- 뒤로/앞으로 이동, 직접 URL, 잘못된 ID, 중첩 Escape, 배경 스크롤 잠금 통과
- 일정 빠른 추가·편집·체류시간 조절·새로고침 지속성·삭제 후 후보 유지 통과
- localStorage 중복/깨진 참조/누락 맵/잘못된 JSON 복구 통과
- 네 가지 목표 뷰포트와 축소된 키보드 높이에서 가로 오버플로 없음
- 앱 코드에서 발생한 console error 및 page error 없음
- 외부 이미지 응답은 네트워크 환경에 따라 실패할 수 있으므로 QA에서는 로컬 픽셀 응답으로 대체했다. UI는 이미지 실패와 무관하게 핵심 동작을 유지한다.

## 현재 데모 한계

- 실제 인증, 네트워크 API, 동행자 초대/실시간 동기화는 없다.
- 지도는 실제 지도 SDK가 아닌 데모 표현이다.
- 데이터 초기화 전용 UI는 없으며 localStorage 키 삭제로 초기화한다.
- 자동화 환경의 포인터 드래그는 브라우저 입력 합성 차이의 영향을 받을 수 있다. 후보 빠른 추가와 일정 편집은 항상 제공되는 대체 경로다.
- Vite 프로덕션 빌드에는 단일 JavaScript 청크가 500 kB를 넘는다는 경고가 남아 있다. 현재 기능 오류는 아니며 라우트 단위 코드 분할은 후속 최적화 범위다.
